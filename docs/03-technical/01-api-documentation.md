# API Documentation — My Vehicle Spend

| Field     | Value                                                                         |
| --------- | ----------------------------------------------------------------------------- |
| Version   | 1.0 (Draft)                                                                   |
| Date      | 2026-10-11                                                                    |
| Base URL  | `https://<project-ref>.supabase.co`                                           |
| API style | Supabase auto-generated REST (PostgREST), RPC, Storage API, one Edge Function |

The app has no custom REST server. The "API" is Supabase's generated interface over the schema in `02-architecture/04-database-schema.md`. Client code should use `@supabase/supabase-js`; the HTTP details below are for reference, debugging and third-party tooling.

## 1. Authentication

### 1.1 Headers (every request)

| Header          | Value                                                                         |
| --------------- | ----------------------------------------------------------------------------- |
| `apikey`        | `<SUPABASE_ANON_KEY>` (public, safe in client)                                |
| `Authorization` | `Bearer <user access token>` (after sign-in) or the anon key for public calls |
| `Content-Type`  | `application/json`                                                            |
| `Prefer`        | `return=representation` (to get inserted rows back)                           |

### 1.2 Auth endpoints (`/auth/v1`)

| Method | Path                                      | Purpose              | Body                                                  |
| ------ | ----------------------------------------- | -------------------- | ----------------------------------------------------- |
| POST   | `/auth/v1/signup`                         | Register             | `{ "email", "password", "data": { "display_name" } }` |
| POST   | `/auth/v1/token?grant_type=password`      | Sign in              | `{ "email", "password" }`                             |
| POST   | `/auth/v1/token?grant_type=refresh_token` | Refresh session      | `{ "refresh_token" }`                                 |
| POST   | `/auth/v1/recover`                        | Password reset email | `{ "email" }`                                         |
| POST   | `/auth/v1/otp`                            | Magic link           | `{ "email", "create_user": true }`                    |
| POST   | `/auth/v1/logout`                         | Sign out             | —                                                     |

**Success (sign-in):** `200` with `access_token`, `refresh_token`, `expires_in`, `user`.

## 2. Data endpoints (`/rest/v1`)

Query syntax: `?column=eq.value`, `order=expense_date.desc`, `limit`, `offset`, `select=col1,col2`. Filters: `eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `in`, `like`, `ilike`, `is`.

| Resource               | Methods                 | Path                            | Notes                                          |
| ---------------------- | ----------------------- | ------------------------------- | ---------------------------------------------- |
| Profile                | GET, PATCH              | `/rest/v1/profiles?id=eq.{uid}` |                                                |
| Vehicles               | GET, POST, PATCH        | `/rest/v1/vehicles`             | `deleted_at=is.null` filter                    |
| Expense categories     | GET, POST               | `/rest/v1/expense_categories`   | System rows have `user_id=is.null`             |
| Expenses               | GET, POST, PATCH        | `/rest/v1/expenses`             | Soft delete by PATCH `deleted_at`              |
| Fuel logs              | GET, PATCH              | `/rest/v1/fuel_logs`            | Create via RPC `add_fuel_log`                  |
| Loans                  | GET, POST, PATCH        | `/rest/v1/loans`                | Schedule generated by client, inserted in bulk |
| Loan payments          | GET, POST (bulk), PATCH | `/rest/v1/loan_payments`        |                                                |
| Loan events            | GET, POST               | `/rest/v1/loan_events`          |                                                |
| Reminders              | GET, POST, PATCH        | `/rest/v1/reminders`            |                                                |
| Monthly spend (view)   | GET                     | `/rest/v1/v_monthly_spend`      | Read-only                                      |
| Fuel efficiency (view) | GET                     | `/rest/v1/v_fuel_efficiency`    | Read-only                                      |

## 3. RPC endpoints (`/rest/v1/rpc`)

### 3.1 `add_fuel_log`

Creates a fuel log and its matching expense atomically. Idempotent on `p_id`.

```http
POST /rest/v1/rpc/add_fuel_log
```

```json
{
  "p_id": "7c2e...",
  "p_vehicle_id": "5b1c...",
  "p_filled_on": "2026-10-11",
  "p_odometer_km": 48210,
  "p_litres": 32.5,
  "p_price_per_litre": 102.4,
  "p_is_full_tank": true,
  "p_station": "HP Pump, Pune",
  "p_payment_mode": "upi",
  "p_category_id": "a1b2..."
}
```

**200 OK** → returns the `fuel_logs` row (`total_amount` = 3328.00).

| Error                                           | Meaning                 |
| ----------------------------------------------- | ----------------------- |
| 400 `23514` check violation                     | e.g. litres ≤ 0         |
| 400 `23514` (message "Odometer … lower than …") | Odometer rule violated  |
| 403                                             | RLS / vehicle not owned |

### 3.2 `record_loan_payment`

Marks an installment as paid, stores the paid amount including late fee / bounce, and creates an EMI expense.

```json
{
  "p_loan_payment_id": "e9b1...",
  "p_paid_on": "2026-11-05",
  "p_paid_amount": 16703.92,
  "p_late_fee": 0,
  "p_bounce_charge": 0,
  "p_category_id": "c3d4..."
}
```

**200 OK** → `{ "loan_payment_id", "expense_id", "status": "paid" }`.

### 3.3 `set_active_flags` (optional helper)

Not required in v1.0. Placeholder for bulk archive of vehicles.

## 4. Storage API (`/storage/v1`)

| Action         | Method & path                                                               | Notes                                     |
| -------------- | --------------------------------------------------------------------------- | ----------------------------------------- |
| Upload receipt | POST `/storage/v1/object/receipts/{uid}/{expense_id}/{n}.jpg`               | Max 5 MB raw; client compresses to ≤ 1 MB |
| Signed URL     | POST `/storage/v1/object/sign/receipts/{path}` body `{ "expiresIn": 3600 }` | 1-hour access                             |
| Delete         | DELETE `/storage/v1/object/receipts/{path}`                                 | Owner only                                |

Storage policy: `(storage.foldername(name))[1] = auth.uid()::text`.

## 5. Edge Function

### 5.1 `POST /functions/v1/delete-account`

- **Auth:** user JWT required.
- **Body:** `{ "confirm": "DELETE" }`
- **Behaviour:** verifies JWT; lists and deletes all objects under `receipts/{uid}/`; calls Admin API to delete the auth user (cascade deletes all rows).
- **Responses:** `200 { "deleted": true }`, `400 { "error": "confirmation_mismatch" }`, `401 { "error": "unauthorised" }`, `500 { "error": "internal" }`.

## 6. Error Format

Supabase returns errors as:

```json
{
  "code": "23514",
  "details": null,
  "hint": null,
  "message": "new row violates check constraint \"expenses_amount_check\""
}
```

The client maps errors to user messages:

| Code / status    | User message                                                              |
| ---------------- | ------------------------------------------------------------------------- |
| 401 / `PGRST301` | "Your session has expired. Please sign in again."                         |
| 403 / `42501`    | "You don't have permission to do that."                                   |
| 409 / `23505`    | "This already exists (e.g. vehicle number)."                              |
| 23514 (check)    | Message from the mapping table in `src/core/errors.ts`                    |
| 5xx / network    | "Couldn't reach the server. Saved on this device; will sync when online." |

## 7. Rate Limits & Quotas

- Auth emails: limited by Supabase project settings (free SMTP quota is low). Use password sign-up for personal use.
- API: no hard request limit on free tier beyond fair-use; keep client polling to a minimum (use refetch on focus, not timers).

## 8. Versioning

The API follows the database schema version. Breaking schema change → new migration + update this document + bump app MINOR version.

## 9. Testing the API

- Use the Supabase Studio "API" tab or `curl` with the anon key and a user token.
- Automated: `tests/api/*.spec.ts` with Vitest (requires a local Supabase stack).
